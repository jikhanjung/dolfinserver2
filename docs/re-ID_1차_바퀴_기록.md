# re-ID 1차 바퀴 — 무엇으로 배웠고 무엇이 나왔나

> 2026-09-07. 지금 화면(`/reid`)이 개체를 제안하는 3자 앙상블이 **무엇으로
> 배운 것인지**를 숫자로 못박아 둔다. 2차 바퀴(개체 90 · 조각 4,000)를 돌고
> 나면 이 문서와 나란히 놓고 읽게 된다 — **그때 "1차가 얼마였더라" 를 다시
> 세지 않으려고** 지금 적는다.
>
> 여기 숫자는 배포된 파일(`reid/v3/cls-*.npz`)과 그때 정답 상태
> (`catalog(as_of=2168)`)에서 **직접 읽은 것**이다. 기억이나 어림이 아니다.

## 1. 배운 자료 — 개체 67 · 조각 1,300

정답 시점은 **개체판정 2,168** 이다. 머리 파일이 `n_labeled = 1300` 을 들고
있어 그 상태를 못박아 준다.

| | |
|---|---|
| 격자 | `reid/v3` · 조각 **7,912** |
| 그중 정답이 붙은 것 | **1,300** (16.4%) — 나머지 6,612 는 안 붙은 채 격자에만 있다 |
| 개체 | **67** |
| 관찰일 | 정답이 있는 날 **72** (격자 전체는 73) · 2016-03-15 ~ 2019-11-05 |

**좌·우를 따로 배운다.** 조각은 앞쪽이 늘 왼쪽에 오게 세운 것이라 한쪽이
거울상이고, 섞으면 한 개체가 두 갈래로 흩어진다.

| | 개체 | 조각 |
|---|---:|---:|
| 좌현 | **61** | **587** |
| 우현 | **60** | **713** |
| 양쪽 다 있는 개체 | 54 | |

머리 파일의 `left_cls`·`right_cls` 가 정확히 61·60 이다 — 자료와 모델이 맞는다.

### 개체당 조각은 아주 고르지 않다

중앙값 **11장**, 평균 19.4, 최소 1, 최대 **116**.

```
   1장      개체   2      조각    2
   2~4장    개체  17      조각   49
   5~9장    개체  12      조각   82
  10~19장   개체  14      조각  202
  20~49장   개체  15      조각  472
  50장~     개체   7      조각  493
```

**상위 7개체가 조각의 38%를 든다.** 개체당 관찰일은 중앙값 5일이고, **하루에만
찍힌 개체가 15** 다(2일 이상 52). 하루짜리는 날로 가르는 자에서 배우는 쪽이나
재는 쪽 한 곳에만 들어간다.

## 2. 멤버 셋 — 계보가 갈려야 표가 갈린다

| | 백본 | 녹인 블록 | 조각 | 차원 |
|---|---|---:|---|---:|
| `fullL` | DINOv3-L (24블록 · 303M) | **14** | 전체 조각 224px (`v3-full224`) | 1,024 |
| `cropL` | DINOv3-L | **16** | **뒷날 크롭** (apex·뒷날·뒷삽입점의 bbox) | 1,024 |
| `megaL` | MegaDescriptor Swin-L-384 (야생동물 re-ID · ArcFace) | **16** | 전체 조각 224px | 1,536 |

셋 다 **같은 자료**(개체 67 · 조각 1,300)로 배웠고, 다른 것은 **무엇을 보느냐**다 —
웹 자기지도로 배운 눈이 전체 모양을, 같은 눈이 뒷날만을, 야생동물 전용으로
배운 눈이 전체 모양을 본다.

**서빙 구조는 임베딩 한 벌 + 선형 한 층이다.** 녹인 블록으로 격자 7,912장의
임베딩을 다시 내면(`reid_chips --emb-only --deep`) 머리는 도로 `X @ W.T + b` 라,
검토 화면 컨테이너에 torch 가 없어도 된다.

```json
{"members": [{"emb": "emb-fullL.npz", "cls": "cls-fullL.npz", "w": 1},
             {"emb": "emb-cropL.npz", "cls": "cls-cropL.npz", "w": 1},
             {"emb": "emb-megaL.npz", "cls": "cls-megaL.npz", "w": 1}],
 "T": 0.65}
```

## 3. 성적 — 폴드 5 · 씨앗 1 · `--as-of 2168` · 질의 1,205

| | top-1 | top-5 | top-10 |
|---|---:|---:|---:|
| 얼린 kNN (기준선) | 28.0 | 59.7 | 71.8 |
| `fullL` 단독 | 84.1 | 94.1 | 96.3 |
| `cropL` 단독 | 87.6 | 96.0 | 97.3 |
| `megaL` 단독 | 81.2 | | |
| **셋의 앙상블 (반반씩)** | **89.9** | **96.7** | **97.6** |

**화면이 내는 것이 이 성적이다** — 채점도 화면도 `reid.ens_logits` 한 함수를
부른다. 온도 `T=0.65` 로 보정해 **평균 확신 89.7% 대 실제 89.9%**(ECE 0.024).

사다리를 한 줄로:

```
kNN 26.7  →  얼린 선형 49.5  →  블록 녹임 84.9  →  뒷날 크롭 87.6  →  계보 셋 89.9
```

## 4. 이 숫자에 붙는 한정 — **실전 성능이 아니다**

- **닫힌 판이다.** 묻는 것이 *"이게 누구냐"* 가 아니라 **"카탈로그 67명 중 몇
  번이냐"** 이고, 답이 반드시 그 안에 있다고 보장된 상태에서 잰 값이다.
  카탈로그 밖 개체를 들이밀면 다섯 개가 전부 틀린다
- **카탈로그가 개체군의 일부다.** 제주 남방큰돌고래가 100~120으로 추정되니
  67은 **6할쯤**이다
- **품질로 걸러진 조각이다.** `reid.usable`(분류·뒷날 보임·밑동·앞쪽·넓이)을
  통과한 것만 든다
- **개체가 늘면 이 숫자는 내려간다. 그리고 그것이 퇴보가 아니다** — 실측으로
  개체 22 → 36 → 67 에서 49.5 → 51.9 → 59.9 였다(얼린 시절 자로)

한마디로 — **"67명 앨범 안에서, 본 적 없는 날의 사진을 주면 열에 아홉은
맞힌다."** *"바다에서 만난 아무 돌고래나 89.9%로 알아본다"* 는 아직 아니다.

## 5. 재는 규칙 — 2차 바퀴에서 이 문서와 나란히 놓으려면

- **날로 가른다.** 무작위로 가르면 같은 날 연사가 양쪽에 나뉜다 (같은 날 짝
  AUC 0.698 대 날 건너뜀 0.480)
- **좌·우를 따로.** 섞으면 한 개체가 두 갈래로 흩어진다
- **`--as-of` 를 붙인다.** 정답이 늘면 문제가 달라져 세로로 비교할 수 없다 —
  **이 문서의 모든 숫자는 `--as-of 2168` 이다**
- **배치 16.** 128 은 같은 에폭에서 걸음 수가 8분의 1이라 −4%p 다
- **차이가 씨앗 폭보다 작으면 아직 차이가 아니다**

## 6. 2차 바퀴에서 물을 것

목표는 **개체 90 · 조각 4,000** 이다 (`reid.GOAL`). 개체 수가 방아쇠이고 조각
수는 동행자다 — 개체당 조각은 대조군에서 진 축이다(`devlog/20260831_002`).

그때 물을 것:

1. **개체 67 → 90 에서 top-1 이 얼마나 내리나.** 내리는 것이 정상이고, 그
   크기를 알아야 3차를 계획할 수 있다
2. **치우침 없는 실사용 정답률** — 2026-09-07 에 `Identification.pred`·`pred_p`·
   `pred_by` 를 붙였다. `source='hand'` 이고 개체판정 번호가 2,168 을 넘고
   상자별 마지막 줄인 것이 그 자다 (`reid_pred` 의 도움말)
3. **`T` 를 다시 잰다.** 머리가 바뀌면 로짓 분포가 바뀐다
4. **증강** — 인수인계 물음 여섯 중 아직 유일한 미답이다 (`fliplr` 은 금지)
5. **거절 문턱** — 중심 거리로는 AUROC 0.561 이었다(`devlog/20260902_002`).
   개체가 늘어 덮개가 넓어지면 그 자리가 달라질 수 있다

## 7. 어디에 무엇이 있나

```
reid/v3/                    화면이 보는 격자 · 멤버 여섯 + ensemble.json
reid/blocks/*.blocks.pt     녹은 블록 셋 (4.1GB) — 격자를 다시 뜨면 이것으로
                            임베딩을 다시 낸다. NAS 레인이 날마다 뜬다
reid/logits/                공유 자로 낸 로짓 세 벌 (폴드 5 · 씨앗 1 · as-of 2168)
```

과정은 `devlog/20260902_001`(매트릭스 90칸) · `20260903_001`(L 곡선과 앙상블) ·
`20260905_002`(얼린 승자를 녹임) · `20260906_001`(화면에 올리는 길과 크롭
레시피) · `20260906_002`(셋째 멤버)에 있다.
