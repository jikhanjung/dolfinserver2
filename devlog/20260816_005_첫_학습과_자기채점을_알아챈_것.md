# 005 — 첫 학습, 그리고 자기 채점을 알아챈 것

2026-08-16 밤. **첫 바퀴 검토를 마치고**(2,315장) 3단계를 한 바퀴 돌렸다 —
내보내기 · 학습 · 추론 · 비교. 화면(`/compare`)도 붙였다.

가장 값이 있는 것은 3절이다. **처음 낸 성적표가 틀렸고**, 그것을 알아챈 뒤
숫자가 뒤집혔다.

## 1. 분류를 묶어서 내보낸다 (`--group`)

DB 는 분류를 열로 들고 있는데 그대로 내보내면 **가슴지느러미 3장짜리
클래스**가 생긴다. 배우는 게 아니라 잡음이고 클래스별 성적도 뜻을 잃는다.

`models.py` 첫 문단의 논지는 **"어려운 음성을 배경에 두지 말라"** 였지 "잘게
쪼개라" 가 아니었다. 묶어도 그 값은 그대로 남는다 — 묶인 것도 여전히 **라벨이
붙은 양성**이다. DB 는 열로 두고 **내보낼 때만** 묶는다.

```
coarse:  fin 2,534 · dolphin 86 (꼬리·주둥이·머리·몸통·가슴) · nonfin 177 (새·사람·기타)
```

사람이 검토 키를 나눌 때 쓴 **돌고래 / 아님** 축 그대로다. 묶음이 분류를
하나라도 빠뜨리면 바로 에러를 낸다 — 조용히 라벨이 사라지는 것이 제일 나쁘다.

`val_date` 는 씨앗에 맡기면 안 된다. 무작위로 뽑았더니 **2016-07-20** 이
걸렸는데, 138장 중 등지느러미가 67장뿐이고 사람이 52장인 날이다. 그날로 성적을
읽으면 뜻을 잃는다. **2019-06-17**(125장 중 등지느러미 124)로 못 박았다.

## 2. `s` 와 `m` 은 같은 자리에 멈춘다

| | 학습 시간 | 파라미터 | `fin` 마스크 mAP50-95 (`val_date`) |
|---|---|---|---|
| `yolo11s-seg` | 60분 | 9.7M | **0.825** |
| `yolo11m-seg` | 110분 | 22M | 0.808 |

전체 평균(세 클래스)에서는 `m` 이 0.007 앞섰지만 그것은 **`dolphin`(라벨
23장) 하나** 때문이었고, 정작 등지느러미에서는 `s` 가 낫다. 사람의 마스크에
대고 재도 `s` 가 이긴다.

**모델 용량이 천장이 아니다.** 파라미터를 2.5배로 키워도 같은 자리에서
멈춘다면 `l`·`x` 는 볼 이유가 없다 — 게다가 `m` 이 이미 11GB 카드의 94%를
쓰므로 batch 16 으로 들어가지도 않는다.

## 3. **정답의 92%가 SAM2 자기 출력이었다**

처음 낸 성적표는 이랬다.

```
SAM2.1   평균 IoU 0.914      YOLO11s 0.902
```

"SAM2 가 더 정밀하고 YOLO 가 더 안정적" 이라고 보고했다. **틀렸다.**

`rules.resolve` 는 사람이 윗윤곽을 안 고쳤으면 **마스크 폴리곤을 그대로 정답으로
쓴다.** 그런데 검토에서 윗윤곽을 다시 그린 것은 2,042장 중 164장(8%)뿐이다.
나머지 2,035장의 정답은 **SAM2 자신의 출력**이다.

```
윗윤곽이 SAM2 것 그대로  2,035장 → SAM2 평균 IoU 0.936
사람이 다시 그린 것        164장 → SAM2 평균 IoU 0.689
```

앞의 0.936 은 **"자기 폴리곤 vs 자기 폴리곤을 밑동에서 자른 것"** 이다. 1이
아닌 이유가 오로지 밑동 아래를 잘라낸 만큼이고, 모델 성적이 아니다. 전체
0.914 는 그 값이 92%를 차지해 나온 것이었다.

### 자를 두 군데 고쳤다

**하나 — 후보도 정답과 같은 밑동에서 자른다.** 정답은 `final_points` 로 잘린
폴리곤인데 후보를 안 자르면 IoU 가 두 가지를 섞어 잰다: 잘라낸 양과 실제 윤곽
차이. 밑동 현은 사람의 판단이고 어느 엔진의 것도 아니므로 양쪽에 똑같이 댄다.

**둘 — `독립` 줄을 늘 함께 낸다.** 사람이 윗윤곽을 직접 다시 그린 것만 센다.

고친 뒤:

| | 전체 (자기채점 섞임) | 독립 164장 |
|---|---|---|
| SAM2.1 | 0.978 | **0.770** |
| YOLO11s | 0.933 | **0.902** |
| YOLO11m | 0.928 | 0.887 |

**두 열의 격차가 곧 자기채점의 크기다** — SAM2 는 0.21, YOLO 는 0.03. YOLO 가
작은 것은 아직 정답을 만든 적이 없기 때문이고, 다음 바퀴엔 반대가 된다.

### 그 독립 164장도 깨끗하지 않았다

그것마저 확인해 보니 **123장이 YOLO 의 학습 자료**였다. 학습에 안 쓴 41장만
보면:

| | 학습에 있던 123장 | 안 쓴 41장 |
|---|---|---|
| SAM2.1 | 0.787 | **0.719** |
| YOLO11s | 0.908 | **0.885** |

결론은 안 바뀌지만 **차이는 부풀려져 있었다.**

## 4. 자기 채점이 학습에는 문제가 아니다

이 절은 검토하던 사람의 지적에서 나왔다 — *"어차피 계속 segmentation 하고
그걸로 더 많은 자료를 만들어 학습시키는 과정을 반복할 거잖아."*

맞다. **사람이 `통과` 를 누른 것은 아무것도 아닌 게 아니라 판정이다.** 모델이
제안하고 사람이 고르고, 고친 것이 다음 학습 자료가 되어 제안이 좋아지는 것 —
그것이 이 저장소의 설계 그 자체이고, 오늘 실제로 일어났다 (`fix` 90% → 50%).

### 표류를 두 번 과장했다

**처음에는** "바퀴가 한쪽으로 굴러가는데 숫자는 아무 말도 안 한다" 고 적고,
검증하려면 **한 날을 떼어 사람이 직접 그려야 한다**고 했다. 두 번 다 물렸다.

첫 번째를 끝낸 것은 이 한마디다 — *"사람은 마스크를 그다지 그리고 싶어하지
않아."* 맞다. **마스크를 처음부터 그리는 것은 이 저장소가 없애려는 바로 그
일**인데, 검증하겠다고 그것을 도로 시키는 꼴이었다. `fix` 를 90%에서 50%로
끌어내리려고 키포인트 모델까지 앞당겨 붙여 놓고서.

두 번째를 끝낸 것은 이것이다 — *"몇 픽셀 틀리는 건 상관이 없고, 그게 누적되면
사람 눈에 띄어서 수정하게 될 거야. 무한정 한 방향으로 강화되진 않아."*

**맞다. 그리고 아래에서 잰 숫자가 그 되먹임이 돌고 있다는 증거다.** 오차가
커지면 눈에 띄고, 띄면 고쳐지고, 고쳐지면 되돌아간다 — 발산하지 않는다.

### 그래서 물음이 달라진다 — **어디서 멈추나**

발산은 안 하지만 0 에서 멈추지도 않는다. **사람이 알아보는 문턱에서 멈춘다.**
그 문턱을 정하는 것은 모델도 자료도 아니고 **검토하는 배율**이다 — 190px
격자에서 보면 격자에서 안 보이는 만큼이 남는다.

그게 문제가 되느냐는 **그 오차를 무엇에 쓰느냐**에 달렸다. 최종 목표는 뒷날
**결각**으로 개체를 가리는 것인데, 결각은 작은 흠이라 하필 그 문턱 근처에
있다. 분할 자체에는 넉넉한 정밀도가 re-ID 에는 모자랄 수 있다.

**그래서 답도 잣대가 아니라 배율이다.** 가끔 편집 창(확대·원본)에서 몇 장만
열어 보면 된다 — 격자에서 통과시킨 것이 확대해서도 통과인지. 그리는 것이
아니라 보는 것이고, 그것이 문턱을 낮추는 유일하게 싼 방법이다.

### 고칠 때의 방향은 공짜로 나온다

사람은 어차피 검토하면서 고친다. 그 고침이 **한쪽으로 쏠리는지**는 새 작업
없이 나온다. 지금 자료로 재 봤다 (사람이 다시 그린 163장, 넓이 비 = 사람 / 모델):

```
중앙값 0.945 · 평균 0.985
줄인 것 113 · 키운 것 49        (1.1배 넘게 키움 30 · 0.9배 아래로 줄임 66)
```

**치우쳐 있다.** SAM2 는 지느러미를 **실제보다 넓게 따는 버릇**이 있고 사람이
그것을 깎아 왔다 — 물보라나 몸통 경계를 붙여 넣은 것으로 보인다.

중요한 것은 **그 버릇이 라벨의 92%에는 안 고쳐진 채 들어갔다**는 점이다.
YOLO 는 그 라벨로 배웠으니 같은 버릇을 물려받았을 수 있다.

| 바퀴 | 봐야 할 것 |
|---|---|
| 지금 (SAM2) | 중앙값 0.945 · 줄임 113 : 키움 49 → **넓게 따는 버릇** |
| 다음 (YOLO) | 1.0 에 가까워지면 버릇이 없어진 것, 계속 0.94 면 물려받은 것 |

이 값이 1 에서 멀다는 것은 **되먹임이 돌고 있다**는 뜻이지 표류한다는 뜻이
아니다. 바퀴마다 이 한 줄을 보면 되고, 새 작업이 들지 않는다.

## 5. `/compare` — 눈으로 보는 자리

`eval_masks` 는 평균과 비율을 내지만 **어디서 틀리는지는 말해 주지 않는다.**
다음 개선점은 늘 나쁜 쪽 꼬리에 있으므로 **기본이 나쁜 것부터**다. 정렬에
"뒤 run 이 더 나빠진 순" 을 둔 것은 새 엔진의 약점을 모으기 위해서다.

계산은 `finseg/evaluate.py` 하나에만 둔다 — 표와 화면이 다른 숫자를 말하면
어느 쪽을 믿을지 알 수 없다 (`rules.py` 를 하나로 둔 것과 같은 이유).

## 6. 두 엔진은 조건이 다르다

| | 받는 것 | 상자를 아나 |
|---|---|---|
| SAM2.1 | 크롭 640 + **상자를 프롬프트로** | 안다 |
| YOLO11-seg | 크롭 640 하나뿐 | **모른다** |

YOLO 는 프롬프트를 받는 모델이 아니라서 **"가운데 것 하나"** 라는 약속으로
대신한다 — 학습 때 `mosaic=0`, 추론 때 프롬프트 상자와 가장 많이 겹치는 것을
고른다. 그 불리함에도 독립 표본에서 크게 앞섰다.

대신 YOLO 는 2,315 중 **5개를 아무것도 못 냈다** (SAM2 는 11개 — 뜻밖에 SAM2 가
더 많다).
