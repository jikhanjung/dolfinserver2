# 002 — 2080ti 환경, 검토 화면의 규칙, 첫 시험

2026-08-15. 저장소를 2080ti(`JikhanDesktop`)로 옮기고 환경을 세웠다. **자료는
아직 안 왔다** — `fin.db` 도 `crops/` 도 NAS 도 이 기계에 없다. 그래서 자료 없이
할 수 있는 것을 했다: 검토 화면이 규칙을 말하게 하고, 시험을 붙였다.

## 1. `sam2 @ git+…` 는 설치되지 않는다

`requirements-gpu.txt` 대로 하면 막힌다.

```
Requested sam2 from git+https://github.com/facebookresearch/sam2.git
has inconsistent name: expected 'sam2', but metadata has 'sam-2'
```

저장소의 패키지 이름이 `sam-2` 라 pip 가 이름이 어긋난다며 거절한다. `sam-2 @
git+…` 로 적으면 지나간다. **파일에 적힌 대로 해서 막힌 것**이라 고쳐 두었다 —
다음 사람이 같은 자리에서 멈춘다.

## 2. `torch.cuda.is_bf16_supported()` 를 믿으면 안 된다

2080ti 에서 **True 를 낸다.** 실제로는 Turing(sm_75) 이라 bf16 텐서코어가 없고,
torch 가 에뮬레이션까지 포함해 답하기 때문이다. 그대로 믿고 bf16 autocast 를
쓰면 조용히 느려진다.

`segment.py:autocast_dtype()` 은 처음부터 **연산능력을 직접 본다**
(`get_device_capability()[0] >= 8`). 확인한 값은 `(7, 5)` 이고 fp16 이 골라진다.
그 판단이 옳았다는 것이 이번에 실측으로 확인됐다 — 근거를 `requirements-gpu.txt`
와 `HANDOFF.md` 에 적어 두었다.

## 3. 규칙을 화면에 띄웠다 — 문구는 파이썬 쪽에 둔다

001 에서 아래 경계를 **밑동 현**으로 정했지만 화면은 그 말을 하지 않았다. 사람이
격자를 보며 점 두 개를 끄는데, 그 두 점이 무엇이어야 하는지 화면에 없으면
**검토가 스스로와 어긋난다.** 첫 100장과 마지막 100장의 기준이 달라지고, 그것은
나중에 되살릴 수 없다.

문구를 어디에 둘지가 유일한 결정이었다.

- **템플릿에 적는다** → 버렸다. 규칙이 `baseline.py` 에서 바뀌어도 화면이
  따라오지 않는다. 판정 규칙을 함수 하나로 모은 것과 같은 이유다
- **`baseline.py` 에 `RULE`·`RULE_POINTS` 로 두고 화면이 부른다** → 채택.
  규칙과 그것을 자르는 코드가 한 파일에 있다

화면에는 한 줄이 늘 떠 있고(`.rule`), 나머지는 `자세히` 를 펴면 나온다. 다섯
줄에는 **틀리기 쉬운 것만** 적었다 — 수면선이 아니라는 것, 잠긴 삽입점은
짐작해서 긋고 `p` 로 표시한다는 것, 꼬리·주둥이에는 긋지 않는다는 것, 첫 제안이
대충이라는 것, 점을 옮기면 그것이 곧 교정이라는 것.

## 4. 시험을 붙였다 — 26개

고른 둘은 **틀려도 눈에 안 띄는 것**이다. 화면은 그대로 뜨고 학습도 그대로
돈다.

| 무엇 | 왜 |
|---|---|
| `rules.label_of` 표 | 축이 넷이라 조합이 말로는 안 잡힌다. `none`(배경)·판정 없음(뺀다)·`edges=neither`(뺀다)가 갈리는 자리를 표로 못 박았다 |
| `geometry` 왕복 | 원본↔크롭이 어긋나면 마스크가 몇 화소 밀린 모습으로만 난다 |
| `crop_rect` | 가장자리에서 **줄이지 않고 미는** 성질, 사진보다 클 때만 줄이는 것 |
| `rules.final_points` | 등지느러미만 자르고 꼬리·주둥이는 안 자른다 |
| 화면의 규칙 | `baseline` 의 문구와 화면이 갈라지는 것을 잡는다 |

`effective_review` 만 데이터베이스가 필요하고 나머지는 저장하지 않은
인스턴스로 돈다. 시험용 SQLite 는 메모리에 뜨므로 **`fin.db` 를 건드리지
않는다.**

시험을 쓰다가 `Review.base_partial` 이 3상태(`NULL`=제안 그대로 · True · False)
라는 것을 다시 확인했다. `resolve()` 가 `is not None` 으로 가르고 있어서 맞다.

## 5. 곁다리로 고친 것

- **`CLAUDE.md` 가 Django 전환을 안 따라와 있었다.** `finseg/db.py`·
  `python -m finseg.*`·`uvicorn` 을 그대로 안내하고 있었고, 세션 시작 시 읽히는
  파일이라 그대로 두면 다음 손이 없는 명령을 친다. 함정 목록의
  `CREATE TABLE IF NOT EXISTS` 항목도 뜻을 잃어 마이그레이션 이야기로 바꿨다
- **`.guides` 심볼릭 링크가 없었다.** 걸었다. 형제 클론 `../devdocs` 가 7/29
  판에서 멈춰 있어 먼저 당겼다 — **링크만 걸었으면 2주 반 묵은 가이드를 보게
  된다.** 끊어진 링크만큼이나 조용한 실패다
- 저장소 안에 `devdocs/` 가 한 벌 더 클론돼 있다 (`.gitignore` 에 없어서
  `git add -A` 하면 딸려 들어간다). 지우는 것이 맞다 — 클론이 둘이면 어느 쪽이
  최신인지 다시 묻게 된다
