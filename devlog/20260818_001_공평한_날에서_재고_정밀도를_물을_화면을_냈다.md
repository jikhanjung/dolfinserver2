# 001 — 공평한 날에서 재고, 정밀도를 물을 화면을 냈다

2026-08-18. `detect-merged` 학습이 8.8시간 만에 끝나 **양쪽 다 처음 보는 날**에서
쟀다. 재현율은 확실히 올랐고, 정밀도는 **잴 방법 자체가 없다**는 것이 드러났다.
그래서 오늘 한 일의 대부분은 그것을 물을 수 있게 만드는 것이었다.

## 1. 학습은 60에폭에서 안 끝났다

|  | 최고 | 에폭 |
|---|---|---|
| mAP50 | **0.9599** | 108 |
| mAP50-95 | **0.6773** | 108 |
| 재현율 | 0.9212 | 95 |

66에폭 시점에 "55~61에서 최고를 찍고 흔들린다, 60에폭이면 됐다" 고 어림했는데
**틀렸다.** mAP50-95 가 그 뒤로도 0.661 → 0.677 로 올랐다. 표본이 짧을 때
잡음을 천장으로 읽은 것이고, 그냥 둔 판단이 맞았다.

## 2. 재현율 — **옛 검출기가 놓친 109개 중 84개를 찾는다**

2016-03-15. 옛 목록에 없고 `detect-merged` 의 `val_date` 라 **양쪽 다 처음
보는 날**이다. 사진 1,109장 · 정답 1,968개.

정답을 **출처로 가르면** 두 모델이 완전히 갈린다.

| | 옛것이 낸 것 (1,859) | **사람이 그린 것 (109)** |
|---|---|---|
| 옛 YOLOv5 | 100.0% | **0.0%** |
| **새 검출기 conf 0.05** | 98.3% | **77.1%** |
| conf 0.25 | 98.0% | 61.5% |
| conf 0.40 | 97.2% | 56.0% |

**옛것이 놓쳐서 사람이 손으로 그려 넣어야 했던 109개 중 84개를 찾으면서, 옛것이
찾은 것의 98.3%를 그대로 유지한다.** 이것이 5단계의 목적이었다 — 재현율의 천장을
올리는 것.

옛것의 "재현율 94.5%" 는 공짜다. 못 찾은 109개가 **정확히 사람이 그린 109개**다 —
자기가 낸 것은 정의상 다 찾는다.

## 3. **정밀도는 잴 수가 없었다** — 오늘 네 번째

| | 낸 것 | 정밀도 |
|---|---|---|
| 옛 YOLOv5 | 1,905 | 97.6% |
| 새것 conf 0.05 | 2,961 | **64.5%** |

64.5%가 그대로 읽히면 안 된다. **정답이 "사람이 인정한 상자" 인데 그 목록은 옛
검출기가 낸 것에서만 만들어졌다.** 새 검출기가 더 뱉은 1,056개는 아무도 본 적이
없어 **자동으로 틀린 것**이 된다.

어제 세 번 만난 것과 같은 모양이고, 다른 것은 하나다 — **이번엔 자를 대기 전에
알아봤다.** 앞의 셋은 숫자를 낸 뒤에 알았다.

## 4. 그래서 물을 수 있게 만들었다

```bash
python manage.py infer_boxes --weights runs/detect-merged-det/weights/best.pt \
    --date <날짜> --conf 0.05      # [GPU] 옛 상자와 안 겹치는 것만 들인다
python manage.py crops              # 크롭이 있어야 화면에 뜬다
#   → 검토 화면 `새 검출` 대기열 (확신 높은 것부터)
python manage.py eval_detect        # 그 판정으로 문턱별 정밀도
```

들인 상자는 `Box` 한 줄이다 — 옛 YOLOv5 상자와 **같은 표에** 들어가고 `source`
와 `run` 과 `conf` 만 다르다. 그래서 크롭·분할·검토·내보내기가 전부 그대로
돌아간다. 사람이 `등지느러미` 라고 하면 그 상자는 곧바로 **검출 자료의 양성**
(옛 검출기가 놓쳐서 아무 라벨에도 없던 자리)이 되고, `아무것도아님` 이면
**공짜로 얻는 어려운 음성**이다. 어느 쪽이든 다음 바퀴에 쓰인다.

### `Box.conf` 를 안 남기면 문턱을 못 고른다

정밀도는 문턱에 따라 64%에서 84%까지 움직인다. 검토를 마친 뒤 "conf 0.4 위에서는
몇 %가 진짜였나" 를 물으려면 상자마다 그 값이 있어야 한다. **한 번 검토하고
문턱은 나중에 얼마든지 옮긴다** — 안 남기면 추론부터 다시 돌린다.
`Box.run` 은 `Mask.run` 과 같은 이유다.

## 5. **`fin.db` 만 보고 견주면 안 됐다** — 하마터면 다섯 번째

처음 돌렸을 때 2016-03-15 에서 새 상자가 **122개** 나왔다. 그런데 `fin.db` 는
**표본이다** — 그 날 사진 92장에 옛 DB 는 상자 189개를 들고 있는데 우리가
들여온 것은 `import_boxes --boxes 2000` 이 고른 **109개뿐**이다.

옛 DB 를 함께 보니 **47개**였다. 나머지 75개는 **옛 검출기가 이미 찾은 것**이다.
그대로 갔으면 사람에게 "새로 찾은 것" 이라며 옛 상자를 보여 주고, 그 판정으로
정밀도를 쟀을 것이다.

**"이 목록이 무엇을 다 담고 있나" 를 물어야 한다.** 어제의 셋은 "이 자가 무엇을
재나" 였는데, 이것은 그 앞 단계다 — 자를 대는 대상 자체가 반쪽이었다.
`--src-db` 를 빼면 명령이 거부한다.

## 6. 마스크 없는 상자를 화면이 어떻게 다루나

들일 때는 폴리곤이 없다. 여기서 묻는 것은 "이 안에 지느러미가 있나" 지
"이 윤곽이 맞나" 가 아니라서 필요가 없다.

- **점선 테두리 + `source` 배지.** 윤곽이 안 그려지는 것이 "분할 실패" 로
  읽히면 안 된다
- **`x`(교정 필요)가 안 눌린다.** "이 마스크가 맞나" 는 마스크가 있어야 물을
  수 있는 말이고(`models.py` 의 "엔진에 딸린 판정"), 서버도 `verdict` 를 안
  적는다. **화면만 바뀌고 저장이 조용히 버리는 것이 이 저장소에서 가장 자주
  겪은 버그다** — 그래서 눌리지 않게 하고 왜인지 말한다
- 그러니 판정은 `PENDING` 으로 남는다. 나중에 `infer` 가 마스크를 얹으면
  **`엔진 바뀜` 대기열에 저절로 뜬다** — 그때 윤곽을 판정한다. 대기열 하나를
  더 만들지 않아도 됐다
- **안 누른 것이 "진짜 지느러미다" 라는 뜻이 된다.** 여기서 재는 것이 바로 그
  비율이라, 손 안 댄 묶음 경고를 `검토할 것` 과 함께 여기에도 걸었다

## 7. 표본이 어디까지 공평한가

`detect-merged` 가 본 관찰일은 10일이고 **우리 표본 20일 중 겹치는 것은
`2016-05-07` 하나**다. `2016-03-15` 는 `val_date` 라 학습에서 빠졌다. 그래서
그 하나만 빼고 **19일 전부에서 공평하게 잰다** — 사진 1,812장에서 새 상자 690개,
그중 conf 0.4 위가 229개다.

**한정이 하나 남는다.** `fin.db` 에는 **옛 검출기가 무언가 찾은 사진만** 들어
있다. 옛것이 "비었다" 고 본 사진에서 새것이 헛보는 것은 여기서 안 잡히므로,
여기서 나올 정밀도는 **낙관 쪽으로 기운다.**
