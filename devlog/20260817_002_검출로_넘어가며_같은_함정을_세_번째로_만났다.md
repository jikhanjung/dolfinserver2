# 002 — 검출로 넘어가며, 같은 함정을 세 번째로 만났다

2026-08-17 오후. 분할이 웬만큼 되니 **5단계(검출기 교체)** 로 넘어갔다. 하루에
같은 모양의 함정을 **세 번** 만났고, 세 번째는 하마터면 결론을 거꾸로 낼
뻔했다.

## 1. 정밀도는 이미 재어져 있었다

옛 YOLOv5 가 낸 상자 2,315개를 우리가 두 바퀴 검토해 뒀으므로, **정밀도는
공짜로 나온다.**

| | | |
|---|---|---|
| 등지느러미 | 2,044 | **88.3%** |
| 사람 | 107 | 4.6% |
| **아무것도 없음** | 82 | **3.5%** |
| 꼬리·몸통·머리·새·주둥이·가슴 | 82 | 3.5% |

**헛것이 3.5%뿐이다.** 여기엔 개선할 여지가 별로 없다.

## 2. 재현율은 **0장의 근거** 위에 서 있었다 — 그런데 자료가 있었다

"이 사진에 지느러미가 몇 마리인데 몇 개를 찾았나" 를 말해 주는 자료가 한 장도
없었다. 우리 라벨은 전부 **검출기가 찾은 것에만** 붙어 있다.

그래서 "사진 100장을 사람이 빠짐없이 표시하자" 고 했는데, 옛 운영 DB 를 열어
보니 **이미 있었다.**

```
dolfinrest_dolfinbox.created_by:  yolov5 999,198 · Xxx_MARC 217 · awesomeemily_marc 113
```

**사람이 직접 그린 상자 330개** — 그게 곧 검출기가 놓친 것이다. 시민과학자들이
3년간 남긴 흔적이 검출기 채점표였다.

사람이 손댄 사진 1,378장에서: 검출기 3,003 · `not_fin` 374 · 사람이 그림 330
→ **재현율 ≈ 88.8%**.

## 3. 첫 검출 실험은 실패했다

사람이 손댄 사진만 모아 817장(상자 1,954)으로 학습시켰다. `2016-03-16` 은
뺐다 — 그날은 사람이 **거르기만 하고 채우지 않아서**(`not_fin` 255 · 추가 0)
놓친 지느러미가 배경으로 들어간다.

`val_date` 2017-08-09 에서:

| | 낸 것 | 정밀도 | 재현율 |
|---|---|---|---|
| 옛 YOLOv5 (conf .25) | 814 | **93.7%** | **81.9%** |
| 새것 conf 0.05 | 1,591 | 47.9% | 81.8% |
| 새것 conf 0.25 | 1,107 | 63.4% | 75.3% |

**어느 문턱에서도 못 이겼다.** 재현율을 겨우 맞추려면 상자를 두 배 뱉으면서
정밀도가 94%에서 48%로 무너진다.

## 4. 옛 학습 설정을 체크포인트에서 꺼냈다

`dolfin_1280_s_100.pt` 는 `models` 모듈이 없어 `torch.load` 가 안 되지만,
pickle 을 직접 훑으면 하이퍼파라미터가 나온다.

```
lr0 0.01 · lrf 0.2 · momentum 0.937 · warmup_epochs 3
mosaic 1.0 ← 우리는 0 이었다
degrees 0.0 ← 우리는 10 이었다
fliplr 0.5 · scale 0.5 · translate 0.1 · hsv 기본값
```

`train.py` 의 `mosaic=0` 은 **크롭 자료의 약속**("가운데 것 하나")에서 나온
값인데, 검출에 그대로 가져다 썼다. 검출은 정반대다 — 사진에서 여럿을 찾는
일이라 모자이크가 바로 그것을 가르친다.

`AUG` 를 갈래별로 갈랐다. 그리고 **같은 자료로 `mosaic` 만 바꿔 대조 실험**을
돌렸다.

| | 최고 mAP50 | 최고 재현율 |
|---|---|---|
| `mosaic 0` | 0.947 | **0.927** |
| `mosaic 1.0` | **0.953** | 0.921 |

**차이가 없다.** 중간(55에폭)에 모자이크 쪽이 재현율 +0.030 으로 앞서 보였던
것은 수렴 속도 차이였고 끝까지 가니 붙었다. 1차 실패의 원인은 모자이크가
아니었다.

(다만 이것은 `val` 기준이고, `val` 은 학습과 같은 날들이라 **모자이크의 진짜
값 — 처음 보는 배경에 대한 일반화 — 을 못 잰다.**)

## 5. **옛 학습 자료가 NAS 에 있었다**

`/mnt/p/JikhanJung/DolFinID/TrainingData/` — 날짜별 폴더에 YOLO 라벨 1,910장.
폴더 이름과 DB `dirname` 이 안 맞아서(`20170809_김녕` 대
`20170809_김녕_annotation`) **날짜 + 파일 이름**으로 이었더니 1,887장이
연결되고 전부 디스크에 있었다.

우리가 만든 817장과 **날짜가 거의 안 겹친다.** 합치면 2,508장 · 관찰일 10일이
되고, 2016-03-15 가 62%였던 쏠림이 풀린다.

## 6. **그런데 `val_date` 가 옛 모델의 학습 자료였다** — 오늘 세 번째

옛 학습 자료 목록에 `20170809`·`20170810` 이 있었다. **우리가 "통째로 뺀 날"
이라며 옛 검출기와 견준 바로 그 날이다.**

```
옛 YOLOv5   재현율 81.9%   ← 자기가 외운 날에서
새 검출기   재현율 81.8%   ← 처음 보는 날에서
```

**조건이 전혀 달랐다.** 새것은 불리한 조건에서 같은 값을 냈고, "못 이겼다" 는
결론이 흔들린다.

오늘 같은 모양을 세 번 만났다.

| | 무엇이 자기 것을 채점했나 | 어떻게 알았나 |
|---|---|---|
| 오전 | SAM2 가 **자기 출력**을 정답으로 (92%) | 정답 출처를 세어 봤다 |
| 오후 | v1 이 **자기 출력**을 정답으로 | `독립` 열을 붙여 뒀더니 두 열이 갈렸다 |
| **저녁** | 옛 검출기가 **자기 학습 날**에서 | 옛 학습 자료를 찾다가 |

**셋 다 "자를 대기 전에 자가 무엇을 재는지 물었어야" 했다.** 앞의 둘은 자를
고쳐 잡아냈고, 세 번째는 자료를 찾다가 우연히 드러났다 — 안 찾았으면 그대로
넘어갔을 것이다.

## 7. 공평한 날이 아예 없었다

| 관찰일 | 옛 YOLOv5 | 우리(`detect-human`) |
|---|---|---|
| 2016-03-15 · 03-28 · 09-22 | 안 봤다 | **봤다** |
| 2017-08-09 · 08-10 | **봤다** | 안 봤다 |

사람이 상자를 채워 넣은 날이 6일뿐인데 **그 6일이 두 모델의 학습 자료로 나뉘어
들어가 버렸다.** 어느 날을 골라도 한쪽이 외운 날이다.

그래서 합본(`detect-merged`)을 만들며 **`val_date` 를 2016-03-15 로** 잡았다 —
옛 목록에 없고, 사람이 상자를 109개 그려 넣은 날이다. **그 자료로 학습해야
비로소 양쪽 다 처음 보는 날에서 잴 수 있다.**

## 8. 이름을 고쳤다

`fin-det-v2` 가 `det-v1` 로 돌린 두 번째 실험인데 이름만 보면 `det-v2` 로 돌린
것처럼 읽혔다. **자료 판과 학습 판이 각각 번호를 갖는 순간 헷갈린다.**

```
datasets/  seg-v1  seg-v2  pose-v1  detect-human(817)  detect-merged(2,508)
runs/      seg-v1-s  seg-v1-m  seg-v2-s  pose-v1
           detect-human-mosaic0  detect-human-mosaic1  detect-merged-det
```

`train` 이 이름을 **자료에서 딴다**(`f"{data.name}-{task[:3]}"`). `Run` 표 20행과
`MANIFEST.json` 의 옛 경로도 함께 고쳤다 — 안 고치면 "이 마스크가 어느 코드에서
나왔나" 를 못 묻게 되고, 그것이 `Run` 표를 두는 이유다.

## 새 명령 둘

**`export_detect`** — 사진 한 장이 학습 이미지 하나다. 사람이 손댄 사진 +
옛 학습 라벨을 합치고, 겹치면 사람이 손댄 쪽을 쓴다. 사진은 복사하지 않고
**심볼릭 링크**로 건다 (장당 10MB 라 복사하면 8.5GB).

**`eval_detect`** — 검출기를 사람이 인정한 상자에 견준다. 옛 검출기는 추론을
안 돌린다(DB 의 상자가 곧 그 출력이다). **사람이 그린 상자가 0개인 날은
경고를 낸다** — 그런 날은 정답이 검출기 출력과 같아져 재현율이 늘 100%로
나오기 때문이다. 실제로 2016-03-16 에서 그렇게 나온다.
