# 003 — 얼린 백본이 천장이었다

2026-08-31 저녁~밤. 오전에 **띠 재분할이 막히고**(`_001`) 저녁에 **개체당
조각 수가 지렛대가 아닌 것**이 나온 뒤(`_002`), `TODOs` 에 남아 있던 마지막
항목을 열었다 — **백본 마지막 블록 녹이기.**

한 줄로 — **오늘 진 것들이 왜 졌는지가 여기서 설명된다.** 넷 다 특징을 안
건드리고 있었다.

## 1. 무엇이 남아 있었나

    ViT-B (768)        졌다   ← 더 큰 **얼린** 백본
    PCA 256            이겼다  ← 오히려 줄이는 쪽
    2층 MLP            졌다   ← 더 큰 머리
    ArcFace 여백        졌다   ← 다른 손실
    뒷날 기하           0.568  ← 특징을 손으로 고치는 길 (`_001` 에서 닫혔다)

**앞의 넷은 전부 얼린 384차원 위에서 논 것**이고, 다섯째는 그 특징을 기하로
고치려던 것이었다. 남은 것이 **특징을 배우는 것** 하나였다.

## 2. 쟀다 — 자릿수가 다르다

같은 5폴드 · 같은 질의 1,205 · 같은 기준선(kNN 26.7 / 55.1 / 70.6, **자릿수까지
같다** — 같은 문제를 풀렸다는 확인이다).

```
                      top-1   top-5   top-10   씨앗 폭
얼린 채 + 선형 한 층    49.5    73.7    82.4    ±0.0
마지막 1블록 녹임      59.4    81.4    88.2    ±0.6
마지막 2블록 녹임      63.9    82.9    89.1    (씨앗 1)
```

**+9.9%p 에 폭이 ±0.6** — 이 저장소 규칙(*"차이가 폭보다 작으면 아직 차이가
아니다"*)을 열여섯 배로 넘는다.

오늘까지 잰 것을 한 줄로 세우면:

```
2블록 녹임         +14.4%p
1블록 녹임         + 9.9
PCA 256 + L1       + 3.2   (8/27)
epochs 400→2000    + 2.7   (고정 문제에서)
2층 MLP            - 1.0
ArcFace 여백       - 2.5 이하
```

**에폭은 값이 없다** — 1블록에서 20 → 40 에폭이 59.9 → 60.4 로 폭 안이다.
**블록 수가 지렛대다.**

### 폭이 넓어지는 것 자체도 자료다

```
얼린 채      49.5 49.5 49.5  →  ±0.0    손잡이     25,795
1블록        59.9 59.8 58.7  →  ±0.6    손잡이  1,800,259
2층 MLP      46.2 ± 0.2~0.5          손잡이    113,000
```

**2층 MLP 는 폭만 넓어지고 성적은 안 올랐다.** 1블록은 폭이 조금 넓어지면서
성적이 크게 올랐다. 그 갈림이 *"용량이 남아돈다"* 와 *"용량이 모자랐다"* 를
가른다.

## 3. 캐시가 이것을 이 기계에서 돌게 했다

재 보니 이랬다.

```
얼린 채 forward 만        76 ms/장
마지막 1블록 녹여 학습     72 ms/장   ← 거의 같다
통째로 녹여 학습          204 ms/장
```

**backward 가 12블록 중 1블록만 타서 forward 가 값을 다 먹고 있었다.** 그리고
얼린 앞 11블록은 **매 에폭 같은 값**을 낸다. 한 번만 계산해 두니 16.6 ms/장
— 4.3배다.

정답 있는 1,300장만 만들어 **81초 · 513MB**. (처음엔 격자 7,912장을 전부
만들어 497초·3.1GB 였다 — 나머지는 배움에도 잼에도 안 들어가는데.)

**대가는 증강을 못 쓰는 것**이다. 앞이 매번 같은 입력을 본다. 그런데도 이겼다.

## 4. 곁들여 나온 것 — 조각이 원본의 절반을 버리고 있었다

`CHIP=128` · `pad=0.15` 이라 밑동 현이 조각에서 `128/1.3 = 98` 화소인데,
**원본에서는 중앙 186 화소**다 (정답 붙은 상자 1,573개에서 잼).

그런데 백본에 넣을 때는 224 로 늘린다.

```
원본 (현 186px) ─[128 로 줄임]→ 98 ─[224 로 늘림]→ 172
                     ↑ 버린다            ↑ 없는 것을 만든다
```

`--chip-size 224` 를 붙였다. **계산이 한 톨도 안 는다** — 백본 입력이 어차피
224 라, 늘려 만든 172화소 대신 진짜 172화소를 넣는 것뿐이다. 256 이면 상자의
41%에서 원본을 넘어 보간이 되므로 224 가 자연스러운 자리다.

**오전에 닫은 띠 재분할과 어긋나지 않는다.** 그쪽은 notch 를 30px 으로 키우려면
4~10배가 필요한데 원본에 1.2배밖에 없다는 것이었고, 이쪽은 **이미 가진 것을
안 버리는 것**이다.

## 5. DINOv3 를 붙였다

라이선스를 받아 가중치 일곱 벌을 `/nas/JikhanJung/models/dinov3/` 에 뒀다
(파일명의 해시와 sha256 이 전부 맞는 것을 확인했다).

**`dinov3s`(ViT-S/16)가 지금 쓰는 `dinov2`(ViT-S/14)와 거의 같다** — 블록 12 ·
384차원 · 21.6M 대 22.1M. **사전학습만 다른 대조**라 ViT-B 처럼 "커져서
이겼나" 를 따로 물을 필요가 없다.

v2 와 v3 는 셋이 다르다.

```
DINOv2   토큰 257 (CLS 1 + 패치 256)              blk(h)
DINOv3   토큰 201 (CLS 1 + storage 4 + 패치 196)   blk(h, rope)
```

`finseg/backbone.py` 한 자리에만 뒀다 — `reid_chips`(임베딩)와
`reid_cls --unfreeze`(녹이기)가 **같은 그물에서 같은 값**을 내야 견줄 수 있다.
어댑터가 v2·v3 둘 다 `m(x)` 와 **비트까지 같은** 값을 내는 것을 확인했다.

## 6. 밟을 뻔한 것 넷

- **`--emb-only` 가 `items.json` 의 `sim` 을 다시 적는다.** 자를 바꿔 보려는
  것뿐인데 **화면의 `닮은 것끼리` 정렬이 바뀌고 다음 레인에 GCP 까지 간다.**
  `--no-chain` 을 뒀다
- **`--emb-name` 기본이 `emb.npz`** 인데 그건 ResNet18 의 512차원이다.
  `--backbone dinov2b` 만 주면 그것을 덮어쓴다
- **`--unfreeze` 가 백본을 박아 두고 있었다.** 열고, 차원이 안 맞으면 멈추게
  했다 — 안 그러면 kNN 은 임베딩으로 재고 분류기는 캐시로 재서 **다른 그물
  둘이 한 표에 나란히 찍힌다**
- **`reid_cls` 에 `cuda` 가 한 줄도 없었다.** GPU 기계에 올려도 CPU 로 돈다.
  `segment.py` 는 GPU 를 쓰는데 이쪽만 안 보고 만든 자리다

그리고 **자기-매칭에 두 번 걸렸다**. 큐를 `pgrep -f 'manage.py reid_cls'` 로
기다리게 했더니 **그 패턴이 제 명령줄을 잡아** 영영 안 끝났다. 걷어내려고
`pkill -f "while pgrep"` 을 했더니 **내 셸을 죽였다.** 지금 큐는 기다리는
로직이 없고, 이어 붙일 때는 **PID 로만** 기다린다.

## 7. 여기서 넘긴다 — GPU 로

m710q 는 4코어라 한 칸이 30분~3시간이다. **그래서 지금 표가 대부분 씨앗
하나이고, `2블록 63.9` 의 폭을 모른다.**

```
1블록 5폴드 씨앗1   30분      RTX 8000 이면 1~2분
6블록 5폴드 씨앗1    3시간
남은 큐 전체         12시간    →  20~30분
```

**224 조각만 여기서 만든다** — `reid_chips` 가 크롭 715MB 를 읽어야 하는데
그건 묶음에 없다. 만든 뒤 CPU 큐는 멈춘다.

### 저쪽에서 바로 시작하는 법

```bash
git clone https://github.com/jikhanjung/dolfinserver2 && cd dolfinserver2
pip install -r requirements.txt
scp -r <계정>@cdgts.paleobytes.info:/srv/dolfinserver2/share/reid-2026-08-31 .
mkdir -p reid/v3 && cp reid-2026-08-31/{chips.npz,items.json,emb-dinov2.npz} reid/v3/

export FIN_DB=$PWD/reid-2026-08-31/fin-public.db FIN_REID=$PWD/reid/v3
SEEDS=3 BATCH=128 scripts/reid_matrix.sh
```

묶음은 **84MB** 다 (사진도 크롭도 안 든다). `reid-mini.npz`(5.3MB)만으로도
되는데, 그러면 규칙 셋을 받는 쪽이 다시 구현해야 한다.

### 저쪽에서 미리 알 것

- **RTX 8000 은 Turing(sm_75)이라 bf16 이 없다** — `CLAUDE.md` 가 2080ti 에
  대해 적어 둔 함정이 그대로 걸린다. 지금 코드는 autocast 를 안 걸고 fp32 다
- **`--batch` 를 키울 것.** 기본 16은 CPU 기준이다. 48GB 면 128도 된다
- **`--as-of` 를 붙일 것.** 정답이 늘면 문제가 달라져 세로로 못 견준다
- **DINOv3 가중치는 따로다.** 라이선스가 계정에 묶여 있다. `dinov2`·`dinov2b`
  는 `torch.hub` 가 알아서 받는다

## 8. 저쪽에서 물을 것

1. **블록 수는 어디서 멎나** — 1→2 가 +4.0 이었다. 3·4·6 을 씨앗 3으로.
   좌현 학습 조각이 500장인데 6블록이면 손잡이가 10.7M 이다. 어딘가에서
   외우기 시작한다 — **폭이 넓어지면서 성적이 안 오르면** 거기가 자리다
2. **224 조각이 값을 하나** — 계산이 안 느는 변경이라 이기면 그대로 먹는다
3. **DINOv3-S 가 DINOv2-S 를 이기나** — 크기가 같아 사전학습만 다른 대조다
4. **ViT-B 를 녹이면 사나** — 얼린 채로는 졌다. 녹이면 다른지
5. **여러 블록에 층별 학습률** — 지금은 전부 `lr 1e-4` 다. `--unfreeze 2` 가
   지면 *"2블록이 안 좋다"* 가 아니라 *"같은 학습률로 2블록은 안 좋다"* 까지가
   정확한 결론이다
6. **증강** — 캐시를 버리면 4배가 든다. GPU 면 그 4배가 아무것도 아니다.
   다만 `fliplr` 은 금지다 (좌·우가 거울상이라)

## 9. 남길 것

- **얼린 특징 위에서 아무리 재 봐야 천장이 안 움직인다.** 오늘 넷을 그렇게
  쟀고 넷 다 ±3%p 안이었다. 블록 하나를 녹이니 +9.9 였다
- **"계산이 안 느는 변경" 을 먼저 찾을 것.** 224 조각이 그것이다 — 백본 입력이
  어차피 224 인데 128 로 줄였다 늘리고 있었다
- **자를 옮길 때는 두 곳이 같은 값을 내는지 비트로 확인할 것.** `backbone.py`
  를 만들면서 v2 경로가 안 바뀌었는지 세 겹으로 봤다
